### 这趟的核心坑（可复用，下次别再踩）
1. **Pages 与 Workers 别选错（本次最大根因）**：Cloudflare 现在两者在 `Workers & Pages → Create` 里是并列 tab，极易误建。选错成 Workers 会连锁导致：部署命令变成 `wrangler deploy`（Workers 命令）、报 Missing entry-point、`functions/` 目录不被识别、D1 绑定被覆盖。**建完要看项目列表的「类型」列确认是 Pages。**
2. **wrangler.toml 必须入库**：D1 绑定写在里面。若仓库无配置文件，每次 Git 部署会用空配置覆盖 Dashboard 手动加的绑定，表现为「绑定不了 / 绑了就掉」。
3. **部署命令用 `npx wrangler pages deploy .`**：`wrangler deploy` 是 Workers 模式，会忽略 `functions/` 目录（非交互下它对 "is this a Pages deployment?" 默认答 no）。
4. **API token 优先让 Cloudflare 自动生成**：项目 Settings → Builds 里删掉自定义 token、选 "Create new token"。自定义 token 极易权限不全，报 `Authentication error [code: 10000]`。
5. **国内站点不要引 Google Fonts**：`<link rel="stylesheet">` 阻塞渲染，国内访问超时 → 首页白屏（后台页没引所以正常，这个现象是很好的诊断线索）。一律用系统字体栈。
6. **Cloudflare Access 按路径拦、不区分 HTTP method**：读写必须拆路径（读 `/api/templates` 公开，写 `/api/admin/templates` 受保护），否则前台匿名 GET 也被挡。
7. **只挡后台页面不挡写接口 = 白挡**：`/admin*` 和 `/api/admin*` 都要保护；绝不能保护 `/api/templates`。
8. 非交互环境下 wrangler 的交互提示都会走 fallback 默认值（如 "Is this a Pages deployment?" → no），容易踩坑，命令要写明确。

## 例图性能优化（图片加载慢）
- **根因不是 R2/CDN**：`cf-cache-status: HIT`、节点 HKG 都正常，纯粹是 **6 张 PNG 原图共 10.6 MB**（单张 1.26–2.68 MB）。
- 解法：用本地 **ffmpeg**（`ffmpeg -encoders | grep webp` 确认支持 libwebp）批量转 WebP：
  ```
  ffmpeg -i 原图.png -q:v 78 输出.webp
  ```
  结果 **10.6 MB → 640 KB，压缩 95%**（0.png 1263→42KB，1.png 2684→202KB，3.png 1783→106KB，4.png 1404→38KB，5-1 2256→141KB，5-2 1699→109KB）。
